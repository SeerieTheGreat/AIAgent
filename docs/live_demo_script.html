Shouhu 守护: Live Demo Script

Five minutes, start to finish: what it is, the features, and a live run on Ethereum Sepolia with real transactions

20 October 2026. Rehearsed in full on Sepolia the same day with the web interface (shouhu-web); every wait below is a measured time from that rehearsal. Companion to the Shouhu Demo Guide (Section 6 explains each screen).

What the rules say about time. The International Track rules (Attachment 2, section 5) set two limits: the demo video is at most 5 minutes (optional, part of the 20 October submission) and the final presentation is at most 10 minutes (Grand Final, on-site defence on 22 November in Shenzhen). The rules do not set a separate length for a live demo. This script runs 4 minutes 50 seconds, so it serves both: record it as the demo video, and use it as the demo inside the 10-minute final (Section 7). If the organisers announce a different slot, Section 7 says what to cut or add.

How it is built. All three scoring criteria are shown on screen, and every wait for the model or the chain is filled with talk, so nobody stands in silence: the speaker always has a line ready for the moment a card appears.

2. Roles and screen

  • Speaker talks to the judges and reads the "Say" column. Driver clicks and types the "Do" column. One person can do both; with two people, the speaker stands, the driver sits at the laptop.
  • One Chrome window, full screen (Ctrl⌘F), light theme. Tab 1 the student's chat, Tab 2 the parent's owner console. Switch with ⌘1 and ⌘2. Proof pages open in a third tab; close it with ⌘W.
  • Keep the side panels visible: if the projector is small and the page drops to one column, set Chrome zoom back with ⌘0. All eight chips above the input box should fit on one line.
  • Chips above the input box send the scripted lines in one click: 2 Mama 20, 3 Landlord 800, 5 Lookalike, 6 Injection are the ones used here. The full text shows in the chat bubble.
  • The rhythm of every turn: click; the receipt card appears first (green paid, amber needs the parent, red refused), then Shouhu's reply. The next chip works only when the reply has finished, so start the next line of talk when the card appears and click when the text stops.
  • A phone timer in the speaker's sight. The checkpoints in the script say what to skip if you are late.

4. Fifteen minutes before

  1. Quit other apps, turn on Do Not Disturb, plug in the charger, hide the bookmarks bar (⌘⇧B).
  2. In Terminal: cd ~/fintechathon/shouhu then uv run shouhu-web --chain sepolia --reset-demo. Wait for press Ctrl+C to stop. --reset-demo removes the accounts, requests, registered contacts and owner activity of earlier runs, so the request is called R1 and both sign-ups start empty. Leave Terminal open behind Chrome.
  3. Tab 1: http://127.0.0.1:8787/?theme=light. It shows Student sign-up; leave it there, it is the opening screen.
  4. Tab 2: http://127.0.0.1:8788/?theme=light. Register the parent now, off stage: name Lin Jianguo, a password, leave both limits empty, Sign with the owner key and register. The Family panel shows the parent with the owner-key signature.
  5. Open https://sepolia.etherscan.io in a new tab, close its cookie notice yourself, then close the tab, so the banner does not cover the page during the demo.
  6. Chinese text: open TextEdit with two lines, 李阿姨 and 给李阿姨转 15 USDC, and copy the first line (⌘C). Or type with Pinyin input if you are fluent. Go back to Chrome, Tab 1.
  7. Use the same short student password every time you rehearse, so it is typed without thinking. Never a real password.

Lines for a long wait (if a card takes more than 25 seconds)

  • "Sepolia makes a block about every twelve seconds. Shouhu reports a payment only after the block confirms it, never before."
  • "The policy engine is plain code with no AI in it: the same request always gets the same decision, and we test it without the model."
  • "Even if the AI were fully compromised, the contract would still refuse anything over the limits; only the parent's key can change them."

6. If something goes wrong

What you seeWhat to do and say
A red card or a red error line mentioning the chain or RPC"The public test network is busy for a moment." Click the same chip again once. If it fails again, move on to the next segment; the proof segment can use any earlier payment.
An error line from the model (authentication, overloaded)Try once more. If it repeats, play the backup video from Section 3 and narrate over it.
The sign-in screen appears in the middle (the server was restarted)Type the password, Sign in. The conversation is gone after a restart, but the chain and the requests are kept.
The request is called R2, not R1Leftover from a rehearsal (no --reset-demo). Use whichever Ask Shouhu to complete button appears; say "R2".
"Address already in use" when startingAnother copy is running: CtrlC in its Terminal window, or quit Terminal, then start again.
Sepolia does not answer at all before the demoStart uv run shouhu-web --chain anvil instead: a fresh local chain, the same pages, the same script. Register the parent again (Section 4, step 4). Say "on a local copy of the chain"; skip Etherscan (the proof page is the record there).
Chinese paste goes wrongType Send 15 USDC to Aunt Li instead; change the line to "the student asks in plain English".

7. A different slot

Shorter (for example 3 minutes)

  • Register the student off stage too (start on the welcome screen): saves 20 s.
  • Skip the injection chip: saves 15 s.
  • Skip Etherscan: saves 10 s.
  • Skip the new contact segment and click chip 8 给哥转 10 for the Chinese input instead: saves 30 s.

Inside the 10-minute final

  • 0:00 to 2:30: deck slides (problem, the three layers, permission tiers).
  • 2:30 to 7:20: this script, with the opening shortened to one sentence because the slides said it; spend the saved 20 s ticking Show tool calls once to show the raw tool calls, or on Pause the agent in the owner console followed by any payment chip (refused: the wallet is paused), then Resume.
  • 7:20 to 10:00: evidence slides: red-team table (8 of 8), tests, the Sepolia hashes and the verified contract source.
